# 逐功能追问清单（grill 风格）

> 用法：对功能清单的每一项（每个 URL/Action/路由）逐组过一遍。能由代码、日志或数据库回答的立即回答；回答不了的标记「待业务确认」。目的：把"看到一个页面"变成"说清一个需求"。

## A. 目的与用户（先回答"为什么存在"）
1. 这个功能解决谁的什么问题？业务目的是什么？
2. 谁在用？什么角色？（对应旧系统哪些权限/角色）
3. 使用频率与场景？（日常高频 / 月底批量 / 管理员专用 / 已无人使用）
4. 如果砍掉，会有什么后果？是否有替代入口？

## B. 输入与校验（页面/接口层）
5. 用户要提供哪些输入？（字段清单：类型、必填、默认值）
6. 有哪些校验规则？（必填、格式、长度、范围、唯一性、业务校验）
7. 校验失败时提示什么？停留在哪一步？
8. 数据从哪来？（表单直填 / 级联选择 / 第三方 / 系统生成）

## C. 处理与状态（业务层）
9. 提交后系统做什么？（写哪张表、调什么服务、产生什么副作用）
10. 有哪些状态流转？状态机长什么样？（初始→…→终态，谁能触发迁移）
11. 有没有定时任务/批处理参与？（Job 频率、处理量、失败重试）
12. 有没有并发/重复提交问题？怎么防的？

## D. 输出与展示（结果层）
13. 成功后用户看到什么？（跳转页 / 列表刷新 / 提示 / 导出文件）
14. 列表页有哪些查询条件、排序、分页？
15. 有哪些展示状态？（草稿/已提交/已审核…）各自显示什么样式？
16. 有没有导出/打印/报表？（文件格式、字段范围、数量上限）

## E. 异常与边界（最容易漏的部分）
17. 空数据时页面显示什么？
18. 非法输入、超时、服务异常时怎么办？
19. 数据删除有依赖时怎么处理？（级联删 / 禁止删 / 逻辑删）
20. 边界值（0、负数、超大数、超长文本、特殊字符）行为是什么？

## F. 权限与数据（横切面）
21. 谁能看、谁能改、谁能删？（页面级 / 按钮级 / 数据范围级）
22. 权限在旧系统里怎么实现的？（拦截器 / 标签 / 菜单配置）——这决定新系统权限模型
23. 涉及哪些表？与其它功能共享哪些数据？
24. 审计/日志要求？（谁在什么时间做了什么）

## G. 迁移决策（收口）
25. 这个功能在新系统里：**保留 / 优化 / 废弃**？
26. 若优化：改哪里？（交互 / 流程 / 技术实现 / 数据模型）
27. 若废弃：下线影响谁？旧数据怎么处理？
28. 验收口径：怎样算"迁移成功"？（给出可测试的输入→处理→输出）

---

## 输出物

对每项功能产出一行「需求澄清记录」：

| 功能 | 业务目的 | 使用者/角色 | 触发与输入 | 关键规则/状态 | 异常 | 权限 | 迁移决策 | 待确认项 |
|---|---|---|---|---|---|---|---|---|
| | | | | | | | 保留/优化/废弃 | |
